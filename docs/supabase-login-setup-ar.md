# إعداد Supabase لتسجيل الدخول والخروج

هذا المشروع يستخدم Supabase Auth. يلزم للواجهة رابط المشروع ومفتاح Supabase العام (`publishable` أو `anon`) فقط. تسجيل الدخول والخروج لا يحتاجان إلى `service_role`.

1. فك ضغط المشروع.
2. انسخ `.env.example` إلى `.env.local` في مجلد المشروع، أو استخدمه كما هو لتعبئة متغيرات البيئة في منصة النشر.
3. شغّل المشروع باستخدام Bun؛ يعتمد ملف الإعداد على `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` للمتصفح، ونسختيهما `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` لتشغيل الخادم.
4. تأكد من أن إعدادات Supabase Auth تسمح بعنوان الموقع المحلي/الإنتاجي عند استخدام روابط تأكيد البريد أو إعادة تعيين كلمة المرور.

`service_role` مفتاح إداري يتجاوز RLS. لا تضعه في `.env.local` الخاص بواجهة المتصفح، ولا في ZIP أو متغير يبدأ اسمه بـ `VITE_`. المفتاح ليس مطلوباً لتسجيل الدخول والخروج. يستخدمه مسار دعوات أعضاء الفريق الإداري الحالي، لذا أضفت اسمه كقيمة فارغة في `.env.example` فقط. ضع القيمة الفعلية في أسرار الخادم/منصة النشر بشكل منفصل؛ لا تضفها إلى ZIP ولا إلى متغير يبدأ اسمه بـ `VITE_`.

ملفات migrations موجودة تحت `supabase/migrations`. وجودها في المشروع لا يعني أنها طُبقت على قاعدة البيانات البعيدة؛ راجعها وطبّقها على المشروع الصحيح قبل استخدام الميزات التي تعتمد عليها.
